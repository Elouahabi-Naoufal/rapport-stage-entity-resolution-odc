\section{Dataset de r\'{e}f\'{e}rence}

\subsection{Donn\'{e}es r\'{e}elles}

Les donn\'{e}es source proviennent de la table \texttt{RFF.formule\_P\_clean} contenant 2\,500\,000 d\'{e}clarations. Les exp\'{e}riences ont \'{e}t\'{e} r\'{e}alis\'{e}es sur un \'{e}chantillon de 10\,000 d\'{e}clarations (349 d\'{e}clarations/entreprise en moyenne).

\subsection{Donn\'{e}es ground truth}

Le fichier \texttt{ground\_truth.csv} contient 520 entit\'{e}s r\'{e}elles avec la correspondance \texttt{ID\_FORMULE} $\rightarrow$ \texttt{company\_id}. Ce fichier n'est jamais utilis\'{e} pendant l'entra\^{i}nement --- uniquement pour l'\'{e}valuation.

\section{R\'{e}sultats des exp\'{e}riences supervis\'{e}es (Exp 0-9)}

\subsection{Exp\'{e}rience 0 --- Baseline synth\'{e}tique}

XGBoost entra\^{i}n\'{e} sur des labels synth\'{e}tiques (m\^{e}me RC = 1, m\^{e}me nom = 1) produit un F1 = 0,063 et un ROC-AUC = 0,520 --- proche du hasard.

\subsection{Exp\'{e}rience 1 --- Audit des labels}

L'analyse r\'{e}v\`{e}le que 100\,\% des paires positives ont \texttt{rc\_exact=1} OU \texttt{name\_exact=1}. Les labels enseignent la r\`{e}gle triviale : ``m\^{e}me RC ou m\^{e}me nom = match''. Le mod\`{e}le n'a rien \`{a} apprendre.

\subsection{Exp\'{e}riences 3-7 --- Pseudo-labeling}

Diff\'{e}rentes strat\'{e}gies de pseudo-labeling ont \'{e}t\'{e} test\'{e}es :
\begin{itemize}
    \item Labels bas\'{e}s sur similarit\'{e} nom + ville $\rightarrow$ F1 = 1,0, AUC = 1,0
    \item 621 paires adjudiqu\'{e}es par IA $\rightarrow$ 79,7\,\% UNKNOWN (insuffisance de preuve)
    \item 126 paires d\'{e}cisives $\rightarrow$ F1 = 1,0, AUC = 1,0
    \item 6\,920 paires difficiles $\rightarrow$ F1 = 1,0, AUC = 1,0
\end{itemize}

\noindent Dans tous les cas, le mod\`{e}le atteint une performance parfaite en validation crois\'{e}e.

\subsection{Exp\'{e}rience 7 --- Test adversarial}

495 paires UNKNOWN sont adjudiqu\'{e}es ind\'{e}pendamment par un humain :
\begin{itemize}
    \item 0 MATCH, 65 NON\_MATCH, 430 UNKNOWN
    \item XGBoost (P $\geq$ 0,9) : 157 pr\'{e}dictions $\rightarrow$ 0 MATCH, 55 NON\_MATCH
    \item \textbf{Pr\'{e}cision adversariale : 0,0000}
\end{itemize}

\noindent Le mod\`{e}le produit des faux positifs en toute confiance. \textbf{Z\'{e}ro valeur ajout\'{e}e.}

\section{Le\c{c}ons d'ing\'{e}nierie}

\begin{enumerate}
    \item \textbf{Le blocage fa\c{c}onne tout} : les r\`{e}gles de blocage entra\^{i}nent le mod\`{e}le EM. Un mauvais blocage enseigne de mauvaises le\c{c}ons qui corrompent toutes les pr\'{e}dictions en aval.

    \item \textbf{Mesurer avant d'agir} : un script de diagnostic du blocage (mesure des paires g\'{e}n\'{e}r\'{e}es par r\`{e}gle) prend 10 minutes et r\'{e}v\`{e}le imm\'{e}diatement les m\'{e}ga-blocs.

    \item \textbf{Les contraintes dures battent les features douces} : la r\`{e}gle de veto RC est une logique m\'{e}tier triviale mais \'{e}limine toute une classe d'erreurs.

    \item \textbf{Les donn\'{e}es synth\'{e}tiques doivent '\^{e}tre algorithmiquement r\'{e}alistes} : des donn\'{e}es visuellement plausibles peuvent \^{e}tre toxiques pour un algorithme ML.

    \item \textbf{La strat\'{e}gie hybride \_R / dirty est indispensable} : les anciens enregistrements sans colonnes \texttt{\_R} doivent \^{e}tre trait\'{e}s par des r\`{e}gles de fallback.

    \item \textbf{Les mod\`{e}les supervis\'{e}s apprennent des shortcuts} : sans labels de qualit\'{e}, XGBoost/LightGBM/CatBoost apprennent des r\`{e}gles triviales et n'ajoutent aucune valeur.

    \item \textbf{Le clustering non supervis\'{e} est plus robuste} : TF-IDF + Leiden produit des r\'{e}sultats interpr\'{e}tables sans donn\'{e}es labellis\'{e}es.

    \item \textbf{La vectorisation est critique} : le calcul de similarit\'{e} cosinus pour 237\,000 paires est pass\'{e} de 30 minutes (boucle) \`{a} 0,8s (matrice numpy).
\end{enumerate}

\section{Dynamique d'ex\'{e}cution concurrente}

Le syst\`{e}me supporte l'ex\'{e}cution de plusieurs pipelines simultan\'{e}ment. Aucun verrou, mutex ou s\'{e}maphore n'existe dans l'architectructure. Chaque ex\'{e}cution dispose d'un contexte isol\'{e} dans le worker Python (thread pool FastAPI). La seule limitation est la capacit\'{e} CPU/RAM du processus Python unique.

\section{Limites de l'\'{e}valuation}

\begin{itemize}
    \item Les donn\'{e}es synth\'{e}tiques ne reproduisent pas n\'{e}cessairement toutes les sp\'{e}cificit\'{e}s des donn\'{e}es r\'{e}elles.
    \item La validation sur un \'{e}chantillon r\'{e}el annot\'{e} manuellement (500--2\,000 paires) n'a pas \'{e}t\'{e} enti\`{e}rement r\'{e}alis\'{e}e durant le stage.
    \item Les performances obtenues ne constituent pas une estimation directe des performances op\'{e}rationnelles.
\end{itemize}

\noindent Deux modes d'\'{e}chec distincts \'{e}mergent :
\begin{itemize}
    \item \textbf{Bottleneck blocage} (entreprises) : les vraies paires ne deviennent jamais des candidats. Le blocking recall de 64\,\% signifie que 36\,\% des vrais matches sont perdus avant m\^{e}me d'atteindre Splink.
    \item \textbf{Bottleneck matching} (sant\'{e}, produits) : les vraies paires sont candidats mais Splink les rejette. Le matching recall de 62\,\%/\,59\,\% indique des probl\`{e}mes de normalisation des formats.
    \item \textbf{Faux m\'{e}langes} (personnes) : la pr\'{e}cision de 40\,\% signifie que 60\,\% des paires accept\'{e}es sont fausses --- les noms g\'{e}n\'{e}riques (Mohamed, Fatima) causent des sur-fusions.
\end{itemize}

\section*{Conclusion}

Ce chapitre a d\'{e}montr\'{e} que le pipeline de production (Splink + embeddings + Leiden) produit 502 entit\'{e}s depuis 10\,000 d\'{e}clarations en 349 secondes. Les 18+ exp\'{e}riences r\'{e}alis\'{e}es illustrent le parcours d'ing\'{e}nierie : des approches d\'{e}terministes aux mod\`{e}les supervis\'{e}s (rejet\'{e}s), puis au clustering non supervis\'{e} (retenu). Le benchmark multi-domain a r\'{e}v\'{e}l\'{e} que la normalisation des champs \'{e}tait l'am\'{e}lioration la plus significative (+0,29 F1 sur sant\'{e}), et que le vrai probl\`{e}me \'{e}tait souvent la g\'{e}n\'{e}ration de candidats (blocking) plut\^{o}t que le scoring des paires. La le\c{c}on principale est que la qualit\'{e} des donn\'{e}es et le blocage sont plus importants que la complexit\'{e} du mod\`{e}le.
