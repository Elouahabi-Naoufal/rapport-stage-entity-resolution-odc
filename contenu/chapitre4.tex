\chapter{Conception, Impl\'{e}mentation et Validation}

Ce chapitre pr\'{e}sente la conception architecturale du pipeline d'Entity Resolution, les choix algorithmiques justifi\'{e}s, l'impl\'{e}mentation technique, et la validation exp\'{e}rimentale sur donn\'{e}es r\'{e}elles et synth\'{e}tiques.

\section{Cadre th\'{e}orique}

\subsection{Mod\`{e}le Fellegi-Sunter}

Le pipeline repose sur le mod\`{e}le probabiliste de Fellegi et Sunter (1969), fondement th\'{e}orique de l'Entity Resolution. Pour chaque paire de records $(r_i, r_j)$, le mod\`{e}le calcule un score de similarit\'{e} :

\[
\log \frac{P(\gamma \in \Gamma_M \mid r_i, r_j)}{P(\gamma \in \Gamma_U \mid r_i, r_j)} = \sum_{k=1}^{n} \log \frac{P(\gamma_k \mid \Gamma_M)}{P(\gamma_k \mid \Gamma_U)}
\]

o\`{u} $\gamma_k$ est la $k$-i\`{e}me comparaison entre les attributs, $\Gamma_M$ l'ensemble des paires correspondantes et $\Gamma_U$ l'ensemble des paires non-correspondantes. Les poids sont estim\'{e}s par l'algorithme EM (Expectation-Maximization).

\subsection{Similarit\'{e} Jaro-Winkler}

La comparaison des cha\^{i}nes de caract\`{e}res utilise la distance de Jaro-Winkler, d\'{e}finie pour deux cha\^{i}nes $s_1$ et $s_2$ :

\[
\text{JW}(s_1, s_2) = \text{Jaro}(s_1, s_2) + \ell \cdot p \cdot (1 - \text{Jaro}(s_1, s_2))
\]

o\`{u} $\ell$ est la longueur du pr\'{e}fixe commun (max 4) et $p = 0,1$ le facteur d'\'{e}chelle. Cette m\'{e}trique est particulièrement adapt\'{e}e aux noms d'entreprises car elle pénalise les transpositions locales tout en tol\'{e}rant les pr\'{e}fixes communs.

\subsection{Vectorisation TF-IDF}

La repr\'{e}sentation vectorielle des noms utilise TF-IDF (Term Frequency-Inverse Document Frequency) :

\[
\text{TF-IDF}(t, d) = \text{TF}(t, d) \cdot \log \frac{N}{\text{DF}(t)}
\]

o\`{u} $N$ est le nombre total de documents et $\text{DF}(t)$ le nombre de documents contenant le terme $t$. Cette approche est plus adapt\'{e}e que les embeddings neuronaux pour les noms d'entreprises marocaines car elle capture les termes discriminants (``SARL'', ``STE'', ``MASR'') sans n\'{e}cessiter d'entra\^{i}nement.

\subsection{Algorithme de Leiden}

Le clustering utilise l'algorithme de Leiden (Traag \textit{et al.}, 2019), am\'{e}lioration de l'algorithme de Louvain :

\begin{enumerate}
    \item \textbf{Initialisation} : chaque n\oe{}ud dans sa propre communaut\'{e}.
    \item \textbf{Phase locale} : d\'{e}placer chaque n\oe{}ud vers la communaut\'{e} maximisant le gain de modularit\'{e}.
    \item \textbf{Agr\'{e}gation} : cr\'{e}er un graphe condens\'{e} o\`{u} chaque communaut\'{e} devient un n\oe{}ud.
    \item \textbf{R\'{e}finition} : fusionner les sous-communaut\'{e}s pour garantir des communaut\'{e}s bien connect\'{e}es.
\end{enumerate}

\noindent La complexit\'{e} temporelle est $O(n \log n)$, contre $O(n^2)$ pour HDBSCAN, ce qui le rend adapt\'{e} aux grands volumes.

\section{Architecture du pipeline}

\subsection{Vue d'ensemble}

Le pipeline est d\'{e}compos\'{e} en 9 \'{e}tapes s\'{e}quentielles, chacune ind\'{e}pendante et testable :

\begin{enumerate}
    \item \textbf{Chargement} : extraction depuis MSSQL avec strat\'{e}gie hybride \_R / dirty.
    \item \textbf{S\'{e}lection} : choix des colonnes pertinentes pour l'Entity Resolution.
    \item \textbf{Nettoyage} : normalisation lexicale (casse, Unicode, ponctuation).
    \item \textbf{Normalisation} : normalisation s\'{e}mantique (dates, t\'{e}l\'{e}phones, identifiants).
    \item \textbf{Splink} : estimation probabiliste des paires par mod\`{e}le Fellegi-Sunter.
    \item \textbf{Identit\'{e} } : application des contraintes d\'{e}terministes (veto, matching garanti).
    \item \textbf{Embeddings} : enrichissement par similarit\'{e} s\'{e}mantique neurale.
    \item \textbf{Clustering} : formation des entit\'{e}s par composantes connexes + Leiden.
    \item \textbf{Mat\'{e}rialisation} : cr\'{e}ation de la table d'entit\'{e}s r\'{e}solues.
\end{enumerate}

Les services communiquent par HTTP/JSON avec deux protocoles :
\begin{itemize}
    \item \textbf{REST} : pour les op\'{e}rations synchrones (CRUD, configuration).
    \item \textbf{SSE} (Server-Sent Events) : pour le suivi temps r\'{e}el des pipelines en cours d'ex\'{e}cution.

\noindent Le worker Python expose un thread pool FastAPI permettant l'ex\'{e}cution concurrente de plusieurs pipelines sans verrou global.

\subsection{Contraintes d'identit\'{e} }

Le pipeline int\`{e}gre des contraintes d\'{e}terministes qui compl\`{e}tent le mod\`{e}le probabiliste :

\begin{itemize}
    \item \textbf{Veto RC} : si deux records ont des RC non-nuls et diff\'{e}rents, la paire est rejet\'{e}e. Cette r\`{e}gle \'{e}limine les faux positifs caus\'{e}s par des noms g\'{e}n\'{e}riques (``PARIS SAS'' vs ``PARIS SARL STE'').
    \item \textbf{Matching d\'{e}terministe} : si deux records partagent la m\^{e}me valeur RC, ils sont automatiquement fusionn\'{e}s.
\end{itemize}

\section{Limites et perspectives}

\subsection{Limites}

\begin{itemize}
    \item Les donn\'{e}es synth\'{e}tiques ne reproduisent pas n\'{e}cessairement toutes les sp\'{e}cificit\'{e}s des donn\'{e}es r\'{e}elles.
    \item La validation sur un \'{e}chantillon r\'{e}el annot\'{e} manuellement (500--2\,000 paires) n'a pas \'{e}t\'{e} enti\`{e}rement r\'{e}alis\'{e}e durant le stage.
    \item Les performances obtenues ne constituent pas une estimation directe des performances op\'{e}rationnelles.
\end{itemize}

\subsection{Perspectives}

\begin{itemize}
    \item Validation du pipeline sur un \'{e}chantillon de donn\'{e}es r\'{e}elles avec revue manuelle des clusters par les experts m\'{e}tier.
    \item Optimisation des performances pour le traitement de 2\,500\,000 d\'{e}clarations.
    \item Int\'{e}gration du pipeline dans le processus de chargement d\'{e}cadeire des d\'{e}clarations.
    \item Am\'{e}lioration du blocking pour les domaines \`{a} faible recall (entreprises, fournisseurs) par ajout de r\`{e}gles de blocage sur t\'{e}l\'{e}phone et email.
    \item Rapprochement automatis\'{e} entre les clusters d'op\'{e}rateurs et la table \texttt{OPERATEUR\_REF}.
    \item Extension du pipeline aux donn\'{e}es RCC.
\end{itemize}
