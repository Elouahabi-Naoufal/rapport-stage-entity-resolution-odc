\subsection{\'{E}tape 1 : chargement des donn\'{e}es}

Le connecteur SQL Server (\texttt{pyodbc}) charge les colonnes s\'{e}lectionn\'{e}es depuis la table source. Un param\`{e}tre \texttt{row\_limit} permet de travailler sur un \'{e}chantillon (10\,000 enregistr\'{e}ments pour les exp\'{e}riences).

\subsection{\'{E}tape 2 : nettoyage}

Le nettoyage applique des transformations g\'{e}n\'{e}riques :
\begin{itemize}
    \item Trim des espaces en d\'{e}but/fin
    \item Normalisation des valeurs NULL (chaines vides, ``NULL'', ``N/A'')
    \item Suppression des caract\`{e}res de contr\^{o}le
    \item D\'{e}duplication exacte des lignes identiques
\end{itemize}

\subsection{\'{E}tape 3 : normalisation}

La normalisation est sp\'{e}cifique au domaine marocain :

\begin{table}[H]
\centering
\caption{R\`{e}gles de normalisation du champ RC}
\renewcommand{\arraystretch}{1.3}
\begin{tabular}{|p{4cm}|p{4cm}|p{5cm}|}
\hline
\textbf{Corruption} & \textbf{Avant} & \textbf{Apr\`{e}s} \\
\hline
Pr\'{e}fixe \texttt{RC/} & \texttt{RC/040178} & \texttt{040178} \\
\hline
Espaces internes & \texttt{040 178} & \texttt{040178} \\
\hline
Tirets & \texttt{040-178} & \texttt{040178} \\
\hline
Majuscules/minuscules & \texttt{rc/040178} & \texttt{040178} \\
\hline
\end{tabular}
\end{table}

Pour \texttt{RAISON\_SOCIALE} : conversion majuscules, suppression accents, ponctuation, suffixes (MAROC). La strat\'{e}gie hybride \texttt{\_R} / dirty est appliqu\'{e}e : si \texttt{\_R} non-NULL, utiliser \texttt{\_R} ; sinon, utiliser la valeur nettoy\'{e}e.

\subsection{\'{E}tape 4 : Splink --- Fellegi-Sunter + EM}

\subsubsection{Cr\'{e}ation du linker}

Le linker Splink est initialis\'{e} avec DuckDB comme backend SQL. Les comparaisons d\'{e}finies comprennent :
\begin{itemize}
    \item \textbf{RC} : JaroWinkler avec seuils 0,95 / 0,80
    \item \textbf{RAISON\_SOCIALE\_R} : JaroWinkler avec seuils 0,95 / 0,88 / 0,80
    \item \textbf{RAISON\_SOCIALE} : JaroWinkler avec seuils 0,92 / 0,80 / 0,70
    \item \textbf{DONNEUR\_ORDRE} : JaroWinkler avec seuils 0,90 / 0,75
    \item \textbf{CODE\_BANQUE\_BAM, GUICHET, CENTRE\_R, VILLE} : ExactMatch
\end{itemize}

\subsubsection{Entra\^{i}nement EM}

Trois sessions d'entra\^{i}nement rotatives estiment les param\`{e}tres $m_k$ et $u_k$ sans donn\'{e}es labellis\'{e}es. Un champ utilis\'{e} dans le blocage d'une session ne peut pas '\^{e}tre entra\^{i}n\'{e} dans cette m\^{e}me session.

\subsubsection{Pr\'{e}diction et veto RC}

Apr\`{e}s entra\^{i}nement, le score de match est calcul\'{e} pour toutes les paires candidates. Le veto RC est appliqu\'{e} en post-traitement : toute paire avec des RC diff\'{e}rents (non-nuls) est rejet\'{e}e.

\subsection{\'{E}tapes 5-6 : d\'{e}cisions de paires et embeddings}

Les paires avec un score $\geq$ seuil sont accept\'{e}es comme matches. Les paires avec un score entre 0,5 et le seuil peuvent '\^{e}tre enrichies par des similarit\'{e}s d'embeddings neuronaux (mod\`{e}le \texttt{multilingual-e5-small}, 384 dimensions).

\subsection{\'{E}tape 7 : clustering}

Deux strat\'{e}gies de clustering sont impl\'{e}ment\'{e}es :

\begin{itemize}
    \item \textbf{Composantes connexes} : simple, d\'{e}terministe, rapide. Chaque composante connexe du graphe de matches devient un cluster.
    \item \textbf{Leiden} : algorithme de d\'{e}tection de communaut\'{e}s (igraph + leidenalg). Param\`{e}tres : r\'{e}solution (granularit\'{e}), nombre de voisins k-NN, m\'{e}trique de distance.
\end{itemize}

\subsection{\'{E}tape 8 : mat\'{e}rialisation des entit\'{e}s}

Chaque cluster est transform\'{e} en une entit\'{e} canonique :
\begin{itemize}
    \item \textbf{ID stable} : \texttt{ENT-\{run\_id\}-\{seq:06d\}}
    \item \textbf{Attributs canoniques} : RC, nom, banque, guichet extraits par vote majoritaire
    \item \textbf{Statut} : \texttt{auto\_approved} ($\geq$0,95), \texttt{review} (0,3--0,95), \texttt{flagged} (<0,3 ou >50 membres)
\end{itemize}

\section{L'interface op\'{e}rationnelle --- la plateforme}

La plateforme web comprend 17 pages fonctionnelles.

\subsection{Pipeline Wizard --- configuration interactive}

Le Pipeline Wizard guide l'op\'{e}rateur \'{a} travers 8 \'{e}tapes de configuration :

\begin{enumerate}
    \item \textbf{Load} : s\'{e}lection de la source de donn\'{e}es, sch\'{e}ma et table
    \item \textbf{Select} : choix des colonnes \`{a} inclure
    \item \textbf{Clean} : options de nettoyage (trim, NULLs, d\'{e}dup)
    \item \textbf{Normalize} : r\`{e}gles de normalisation (NFC, format date/t\'{e}l\'{e}phone)
    \item \textbf{Splink} : type de liaison, blocage, comparaisons, seuil, it\'{e}rations EM
    \item \textbf{Embeddings} : activation, mod\`{e}le (e5-small/base/large), colonnes textuelles, poids
    \item \textbf{Cluster} : strat\'{e}gie (CC ou Leiden), seuil d'ar\^{e}te, r\'{e}solution
    \item \textbf{Finalize} : nom de la table de sortie
\end{enumerate}
